# 余席扣待确认说明（BUGFIX-14）

> 方案钉死日：2026-11-22。当日定稿后不得改口。走偏即记「余席扣待确认偏航」。

## 缺陷

余席公式漏计待确认：展示口径为 `capacity - booked`，把仍处于 `占位中` 的
待确认占位当成已释放，于是页面上显示可订，一点占位就被真实容量校验（占位服务
本就扣了待确认）以满档打回。假绿夹具见 `fixtures/remaining_false_green.json`。

## 正确性口径（二选一，钉死为甲）

余席必须扣待确认。正确性只走以下两路之一，**两边不得混用**：

- **甲（采用）：余席同事务重算。** 在档锁内、与占位写操作同一事务中，
  按 `capacity - booked - Σ(占位中 seats)` 重算余席，并把结果写回档期行
  作为展示余席（`slots.remaining`）。任一步失败，事务不提交，展示余席滚回旧值。
- **乙（不采用）：校准影子切换。** 先写校准影子，再原子改展示余席；
  失败则影子作废、余席零改。

本仓库只走甲。不引入影子表、不做影子晋升、不与乙混用。

## 落点

- 档锁：`slot:{code}`。占位写与余席读都要先抢档锁（`locks.require_lock`）。
  后到者只写 `contention_log` 争用痕，不写业务、不改余席。
- 单一重算函数：`backend/remaining_svc.py` 的 `recompute_remaining(conn, slot_id)`，
  读容量/已订/待确认三项，写回 `slots.remaining`，返回重算值。同一事务内调用。
- 服务改造：占位服务、档期服务、对账服务、审计服务均经该函数取余席；
  占位/确认/候补晋升/关档等改动 `booked` 或 `占位中` 的路径，写业务后同事务重算写回。
- 展示：余席一律读服务端 `remaining`。**禁止只在前端减一**，不得在前端做任何余席算术。

## 五处同态

余席页（档期详情/列表）、待确认行（占位单）、候补页、对账页、审计页
必须读到同一个 `remaining` 值，全部来源为档期行写回值。
